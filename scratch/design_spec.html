5to1r

Website Design Specification — Every page, every component, every word.

Design direction: Dark, sharp, precise. Developer-grade aesthetic.

Logo typeface: Vercel Geist Pixel — pixel-perfect, technical, unmistakable.

Body typeface: Geist Mono (primary UI) + Geist Sans (prose). Both by Vercel. Geist Pixel for logo only.

Component system: shadcn/ui (base), Recharts (span timelines), Tremor (dashboards), Framer Motion (micro-animations).

Background: #0A0A0A near-black. Not pure black — pure black flattens depth. Near-black creates dimension.

5to1r Python SDK — quickstart

# Python — 2 lines to instrument any agent

from fivetoone import trace_agent, llm_call, tool_call

@trace_agent(api_key='5t1r_your_key')

async def research_agent(query: str):

result = await llm_call(model='claude-sonnet-4-5',

prompt=query)

sources = await tool_call('web_search', query=query)

return result

14 — Mobile Considerations

5to1r is primarily a desktop product — developers use it on large screens while coding. Mobile must be functional but it is not the primary surface.

Page

Mobile adaptation

Landing page

Single column. Hero: headline + CTA only. Code preview hidden. Feature sections stack vertically.

Sign up/in

Full-width Clerk component. Brand panel hidden.

Dashboard

Sidebar hidden. Top hamburger menu opens a drawer overlay. Stat cards: 2x2 grid. Charts: full width, height reduced to 200px.

Trace viewer

Timeline fills full width. Summary panel collapses to a tab row below the timeline.

Runs list

Table reduces to: Status / Run ID / Cost. Other columns hidden. Tap row to expand inline details.

Pricing

Cards stack vertically. Pro card is first in the stack.

15 — Animation & Motion Specification

5to1r is a precision tool. Animations are functional, not decorative. Every animation has a job.

Principles

  • Duration: 150ms for micro-interactions (hover, focus). 250ms for panel transitions. 400ms for page-level transitions.:
  • Easing: ease-out for entrances. ease-in for exits. No bounce, no spring unless there is a specific reason.:
  • No animation just for decoration. If removing the animation breaks the UX — it stays. If not — it goes.:

fade

Opacity 0 → 1. 150ms. Applied at the layout level via Next.js route transitions.

Button hover

brightness

Primary: brightness 110%. Ghost: text colour to white. 150ms. No scale, no translate.

none

Static. No animation. The orb is ambiance — movement would be distracting on a landing page.

draw-on

Recharts and Tremor built-in: lines draw from left to right on first load. 600ms. Signals fresh data.

Skeleton loading

shimmer

shadcn <Skeleton>. Linear-gradient sweep left to right. 1.5s infinite. Used on all data-dependent UI.

The design principle in one sentence.

"Every element must earn its place. If you can remove it and the page still works — remove it."
